# fixture-app-maps.txt
#
# A SYNTHETIC /proc/<pid>/maps capture, hand-built for labs/lab-01 and
# labs/lab-04.
#
# READ THIS BEFORE YOU TRUST A NUMBER IN IT.
#
# This file is NOT a capture from a real device. It is constructed, and it is
# constructed for a reason: on a stock Android 13 device an ordinary `adb
# shell` (uid 2000, SELinux domain u:r:shell:s0) is DENIED read access to
# another app's /proc entries entirely --
#
#     $ adb shell head -3 /proc/$(pidof zygote64)/maps
#     head: /proc/541/maps: Permission denied
#
# -- which was verified on the device this chapter was written against. So a
# lab that says "now read the target app's maps" cannot be done by a reader
# without root, and a fixture is the honest alternative to pretending
# otherwise.
#
# The STRUCTURE is faithful: the segment counts, permission patterns, region
# names, the boot image and OAT layout, the ART space names and the Scudo
# region names all match what a Zygote-forked app process really looks like.
# The ADDRESSES are invented and internally consistent. Do not quote an
# address from this file as evidence of anything.
#
# What has been planted in it, for the labs to find:
#   - one rwxp anonymous region that is NOT the JIT cache
#   - one executable mapping of a file that has been unlinked
#   - one executable mapping backed by an anonymous file object
#   - one executable .so under /data/ that is not inside an APK
#   - one MAP_SHARED writable file mapping
#   - one execute-only (--xp) system library segment
#   - the legitimate JIT cache, so that "rwxp" alone is not the answer
#
# Analyse it with:
#     python3 ../scripts/maps-analyse.py fixture-app-maps.txt
#     python3 ../scripts/maps-analyse.py fixture-app-maps.txt --gaps
#
